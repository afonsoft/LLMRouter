# Paridade OmniRoute + 9router → LLMRouter — análise completa (2026-10-10)

Comparativo da migração/refatoração **OmniRoute (diegosouzapw/OmniRoute, Next.js/React/TS)
+ 9router (decolua/9router)** para **LLMRouter (.NET 10 + Blazor WASM + EF Core/SQLite)**.

- Pin do contrato: OmniRoute `61e07fb7e` (2026-10-08), 9router `ce4460e` (v0.5.99).
- Upstream seguiu andando: `release/v3.8.52` hoje = `048d9e2f2` + ~34 commits novos (delta abaixo).
- Foco do projeto (decisão do dono): **gateway + routing rodando em docker** —
  proxy pessoal, auth de CLI, Electron/desktop fora de escopo.

## 1. Quadro geral

| Métrica | OmniRoute (pin) | LLMRouter | Nota |
|---|---|---|---|
| Stack | Next.js/React/TS, better-sqlite3, Electron | .NET 10 minimal API + Blazor WASM, EF Core SQLite | reescrita total, não transpilação |
| Rotas HTTP (arquivos) | 748 `route.ts` | ~525 rotas mapeadas (50 arquivos de endpoints) | LLMRouter consolida verbos/CRUD no mesmo path |
| Cobertura nominal de rotas | — | ~257 caminhos idênticos + ~230 equivalentes renomeados | renomeado: `provider-connections/*`, grupos `{p}` para tunnels/services/local redis, `settings` consolidado |
| Páginas | 149 `page.tsx` | 132 `@page` (0 placeholders — catch-all só p/ 404) | settings/* e radar/* consolidados em páginas seção |
| MCP tools | ~69 `omniroute_*` | 32 (+ `chat__*` por combo) | gap de ~37 tools |
| Catálogo providers | ~134 arquivos TS (apikey/oauth/noauth/web-cookie/…) | 288 entradas `providers.json` | merge dos dois catálogos + extras |
| Persistência | 202 migrations SQLite | EF Core `EnsureCreated`, tabelas espelham nomes upstream | mesma estrutura `providerConnections`, `apiKeys`, `combos`, `usageHistory`, `kv`… |
| Testes | vitest + Playwright | **449 casos** xUnit/Shouldly + e2e smoke `node e2e/smoke.mjs` | suite serial, sem paralelização por statics compartilhados |
| Specs | — | 87 specs escritas, **87 entregues** (SPEC-080 não existe) | um branch+PR por spec, merge auto no check verde |

## 4. Avaliação da refatoração

**Funcionou bem:**
- Espelhamento de schema (tabelas `providerConnections/apiKeys/combos/usageHistory/kv` homônimas) —
  dados migráveis e debugging comparável.
- Dual-mount `/v1`+`/api/v1` e i18n por namespaces — contrato preservado.
- Consolidação sensata de rotas (tunnels/services/redis por `{p}`) — menos superfície, mesma função.
- Pipeline de gateway único (`Passthrough` c/ auth/rate-limit/plugins/chaos/cascade/usage) usado por
  toda a media surface — bom reuso.
- 449 testes serializados; CI c/ e2e + perf gate (≥30 rps) + sonar sweep (dup<3%).
- Headless + Dockerfile + compose + porta 20128 alinhada — alvo docker coerente.

**Débito técnico conhecido:**
- `kv` single-row JSON blobs (audit/memory/webhooks) — particionamento iniciado (SPEC-087) mas quente.
- `llmlingua`/`omniglyph` compression = stubs (precisam sidecar real via ServiceManager).
- MITM real (CONNECT+TLS) não implementado — só forward-proxy HTTP.
- OIDC/login social ausente (só password local + apiKeys).
- Registry caps: `supportsVision/toolCalling/supportsReasoning` × `vision/capabilities` — SPEC-087
  criou overrides, falta mapear campos do registry (upstream agora persiste caps no sync — ver delta).
- Algumas superfícies `/api` são thin (audit events, guardrails, mcp mgmt, rtk, agent-skills) —
  páginas existem mas sem API dedicada upstream-equivalente.
- Páginas legais/erro ausentes (privacy/terms/offline/forbidden/maintenance/forgot-password).

## 5. Recomendação de ordem (foco docker/gateway)

1. **Probes**: `/healthz` `/livez` `/readyz` (micro — docker/k8s precisa).
2. **`/v1/providers/{p}/*`** — superfície scoped por provider (8 rotas, gateway puro).
3. **`/v1` leftovers**: `responses/input_tokens`+`responses/{*}`, `models/{*path}`, `relay/.../bifrost`,
   `agents/*`, `registered-keys/{p}/revoke`, `batches/delete-completed`, `vscode raw/combos mirrors`,
   `management/proxy-subscriptions` detail.
4. **Usage/logs depth**: call-logs/request-logs/proxy-logs + combo-{forecast,health-dashboard,
   scoring-inspector,trace} + route-explain — maior gap analítico; alimenta as páginas existentes.
5. **Mgmt ausentes**: guardrails API+test, mcp mgmt (tools/status/restart), quota groups+pools CRUD,
   keys sub-resources, webhooks detail, pricing sync, models catalog/test-all.
6. **Micro-spec delta upstream**: nadir strategy + combo auto-prune + registry-caps-from-sync +
   sanitizer/SSE follow-ups + `max_tokens` floor + reasoning-effort discovery.
7. **MCP tools** baratas (batch ~15: pool_*, set_*, simulate/explain/route_request, ccr_*, cache_*,
   get_*_metrics, db_health_check, tool_search).
8. **Auth OIDC** se o docker for multi-usuário; caso contrário baixíssima.
9. **Depois**: agent-skills/acp backends dedicados, rtk context endpoints, sync/*, modality-bridge,
   memory item ops, conversations tree, plugins activate/config, gamification/radar detail, páginas legais.
10. **Backlog/nicho (fora de escopo)**: cli-tools settings, oauth per-provider import, agent-bridge/mitm
    desktop, settings/proxies egress ops, cloud/*, `/v1/{completions,alpha/search,api/chat}`, `/v1/{*}`.
